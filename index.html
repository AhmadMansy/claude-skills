01 · Primer

What a skill actually is

A skill is a folder containing a SKILL.md file and, optionally, scripts and reference files. Claude loads it in stages. You can install dozens of skills, and each one stays almost free until a task needs it.

1

Metadata is always loaded

Only the skill's name and one-line description sit in context. Claude uses them to decide when the skill applies.

~ tens of tokens per skill
2

SKILL.md loads when it applies

When a task matches, Claude reads the instructions: the workflow, conventions and checklists.

~ a few thousand tokens, only when used
3

Resources load on demand

Scripts, templates and reference docs are opened or executed only when a specific step needs them.

effectively unbounded, paid for only when used

From your shell: the skills CLI

# any GitHub repo that contains SKILL.md files
$ npx skills add <owner>/<repo> --skill <name>
# or by hand: drop the folder into
$ ~/.claude/skills/<name>/SKILL.md

      05 · Field notes
      
Install wisely

    

    

      
🔍
Read SKILL.md before installing
Skills can include scripts that run shell commands and read your files. Treat a community skill like any other dependency: read it, pin it, and prefer well-known authors.

      
🧩
Avoid overlapping skills
Taste, Impeccable and UI/UX Pro Max all target the same problem. When two descriptions match the same task, Claude may pick the wrong one. Keep one skill per job.

      
📊
Install counts are rough signals
Install and star counts come from directories and vendor blogs, and many roundups are written by companies that rank their own tools. The tiers here reward picks that independent lists agree on.

      
🛠️
Write your own skill when none fits
When you've explained the same convention to Claude three times, use skill-creator to turn it into a skill. Team-specific skills often beat anything public.

      
🏢
Project skills vs. personal skills
Put repo conventions in .claude/skills/ so your team gets them through git. Keep personal workflow skills in ~/.claude/skills/.

      
🎯
Game engines: text-based formats work best
Godot's text scenes work well with Claude. Unity and Unreal keep much of their state in binary assets and the editor, so expect to supply more context there.
